    What's New in Actian MCP Server 1.2.0¶

    Actian MCP Server 1.2.0 adds the following features and changes:

    • Actian VectorAI DB Support
    • Multi-Target Deployments
    • Resource-Server Mode
    • Ingres Health Tools
    • Analytics Engine Vector Search
    • HCL Informix Updates
    • Zen Updates
    • NoSQL Updates
    • Tool Annotations and Tool Changes

    Actian VectorAI DB Support¶

    Actian MCP Server 1.2.0 introduces the Actian MCP Server for VectorAI DB. An AI agent can run semantic search over vector collections. The server shows only the collections listed in conf.json.

    • Tools: Six read tools search, count, and page through collections. search embeds the query text, and search_by_vector takes a vector from the caller.
    • Writes: Writes are off by default. With query_mode set to read-write, four write tools create collections and store or delete points. Each write needs approval from the person at the Model Context Protocol (MCP) client.
    • Embeddings: The server can embed text with OpenAI, Gemini, or any server that offers the OpenAI embeddings API. With the none provider, the caller supplies the vectors.
    • Resources and prompts: Health, the collection list, and each collection's details are MCP resources. The find_information and store_information prompts guide an agent.
    • Security: The server supports OAuth with Auth0 or Keycloak, and resource-server mode. When the engine requires authentication, the server sends an engine access token from vectorai.api_key_secret.
    • Operations: A call log writes one record per tool call. Custom extensions add tools and resources.
    • Container defaults: The image has no built-in conf.json; a container started without a mounted configuration exits with Configuration file not found. The compose file and the Quick Start publish port 8000 on 127.0.0.1; MCP_SERVER_BIND_ADDRESS opens it for OAuth deployments.

    For more information, see Actian VectorAI DB.

    Multi-Target Deployments¶

    One container can now serve many databases instead of running one container for each database. You list the databases in a targets block in conf.json. Each database gets its own URL, and OAuth scopes control access to each database separately. You can add or remove targets without restarting the server by using targets.d files. A deployment without a targets block works as before.

    • Each database in a target entry can have its own user name and password.
    • A caller whose token has no grant for a database gets 403 Forbidden with insufficient_scope. The error names the missing scope.
    • If a request does not name a database, the server tells the client which URL to use.

    Multi-target deployments work with Actian Ingres, Actian Analytics Engine, HCL Informix, and Actian Zen. Zen also supports read-only personas, which are named connections that open a database in read-only mode.

    Actian NoSQL also serves several databases from one server, through named targets in application.properties. Each target gets its own URL, /mcp/{target}, and its own read and write scopes. Targets kept in a directory are added, changed, and removed without a restart.

    For more information, see Ingres, Analytics Engine, HCL Informix, Zen, and NoSQL.

    Resource-Server Mode¶

    An application that has already signed the user in can now call the MCP Server with an access token from the identity provider (IdP). The user does not need a second OAuth login. The server checks each token against the IdP's published signing keys and runs the call as the user named in the token. The Auth0 and Keycloak guides describe the IdP setup, including the scopes for each target, and how a calling application gets a token.

    For more information, see Ingres, Analytics Engine, Zen, and VectorAI DB. HCL Informix enforces per-target grants in resource-server mode. No Informix setup guide is available yet. See HCL Informix Authentication.

    Ingres Health Tools¶

    Seven built-in, read-only tools report the health of the Ingres installation and the connected database. An AI assistant can use them to answer questions about checkpoints, locks, and optimizer statistics without catalog queries.

    For more information, see Health Tools.

    Analytics Engine Vector Search¶

    The server now shows an AI agent which columns are VECTOR columns. The vector_search tool returns the rows nearest to a query vector. VECTOR columns require Analytics Engine 8.0 or later.

    For more information, see Vector Search.

    HCL Informix Updates¶

    HCL Informix now supports multi-target deployments. Each database in the registry gets its own URL and its own schema resource, and list_accessible_targets lists the databases a caller can reach. The server keeps its Open Database Connectivity (ODBC) connection settings in sync with targets.d files, so you can add a database without restarting it. When a query fails, the server log no longer records the SQL text.

    For more information, see Multi-Target Deployments and Resources.

    Zen Updates¶

    Zen now supports several databases from one server and resource-server mode. It also adds a call log, the list_accessible_targets tool, tool annotations for each mode, and a Deployment Scenarios page.

    In orm_operation, an update or delete no longer accepts where. Use entity_id for a single row, or execute_write_query for a conditional UPDATE or DELETE.

    The image no longer contains a default conf.json: a container started without a mounted configuration exits with Configuration file not found instead of serving DEMODATA. The compose file, the start-zen-mcp.ps1 launcher, and the Quick Start publish port 8000 on 127.0.0.1 by default; MCP_SERVER_BIND_ADDRESS (compose) and -BindAddress (launcher) open it for OAuth deployments.

    For more information, see Zen and Deployment Scenarios.

    NoSQL Updates¶

    • One server can serve several NoSQL databases through named targets. Each target has its own URL, /mcp/{target}, and its own read and write scopes, and targets kept in a directory are added, changed, and removed without a restart. See Multi-Target Deployments.
    • Each database has a call cap, nsql.db.max-calls (default 10), and a deadline for read calls, nsql.db.call-deadline (default 30s). A call beyond the cap is refused as busy, and a read that runs past the deadline is stopped. The server reconnects to a database that comes back, without a restart.
    • The server accepts a token only when its aud claim contains a value set in quarkus.oidc.token.audience. The Keycloak guide also describes token exchange for a calling application.
    • The server supports the stateless 2026-07-28 version of MCP. A client on it confirms a write by repeating the tool call.
    • get_objects_by_loids lists the Logical Object IDs (LOIDs) it did not find in notFoundLoids.
    • For extension authors, the declared return type of a tool, resource, resource template, or prompt decides what the client receives, and some return types stop the server at startup.

    For more information, see Targets, Database Availability, Authentication, Protocol Versions, and Extensions.

    Tool Annotations and Tool Changes¶

    • Each tool declares MCP tool annotations. Clients can use them to decide whether to run a tool without asking first.
    • For Ingres, list_indexes lists the indexes on a table.
    • For Ingres, list_tables shows each table's owner, and describe_table accepts an owner-qualified name.

    For more information, see Ingres Tools.
